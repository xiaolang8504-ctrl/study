# 2026-09-21 学生网页 P0 交付与预发验收

## 基线与部署顺序（B01）

当前工作区在本轮开发前已有约 2600 个与 budget→study 迁移有关的暂存/未跟踪文件，`HEAD=a290cbaf4eb3ad24e4b07ffda53319bbd8fe00e7` 不是可部署的智错本版本。发布时须从独立、已提交的固定提交构建，并按“受管 SQL → 后端 → 前端 → 端到端验收”留存各制品 SHA256。不要将这个 HEAD 当作本轮发布基线，也不要直接用当前脏工作区发布。建议把已有大批改动分成基础迁移、业务后端、前端、P0 修复四组审查提交；不得通过重置工作区制造干净基线。

系统服务从 Nacos 读取 `database-config.yaml`、`redis-config.yaml`、`security-config.yaml`、`msg-service.yaml`、`log-service.yaml`；部署前逐项核对 MySQL 8、Redis、网关、OCR、文件根目录、邮件、ClamAV、字体、Nacos 命名空间和访问控制。密钥只在 Nacos/密钥管理中设置。本地 `bootstrap.yml` 的 Nacos 地址与网关路由必须按部署环境覆盖。确认管理 API 不在 `security.ignore.urls`。

受管 SQL 由 `GeneratedSqlMigrationRunner` 按文件名顺序执行，使用数据库锁、脚本 MD5 历史及失败审计。`scripts/verify_managed_sql.py` 对仓库中 13 个受管脚本做 SHA256 清单校验；新增迁移须审查后更新清单。此次新增 `20260921_guardian_web_menu.sql` 和 `20260921_review_mastery_evidence_reset.sql`。先对数据库做快照，再在空库和从旧版升级的库各启动两次；核对 `sys_generated_sql_migration` 的脚本数不因第二次启动增加，审计表无 `FAILED`，并留存数据库快照 ID、应用制品 SHA、日志和执行人。

旧“已掌握”没有独立且跨间隔的证据时，迁移将其备份到 `review_legacy_mastery_reset`，然后退回“已订正”，清除相应复习项的旧掌握时间及连续次数。部署前记录受影响行数；上线后可查询备份表向学生解释状态变化。若必须回滚，优先从部署前数据库快照整体恢复。仅在确认没有新学习写入时，可按备份表恢复 `sys_wrong_question.status` 和 `sys_review_item.mastered_time`；有新写入时不能机械覆盖学生新进度，应逐题审核。

## 主链路回归（B02）

在预发真实依赖、同一固定版本上，用两个学生账号 A/B、一个家长账号和至少一份获授权去标识化多页 PDF 执行下表。每步保存请求 ID、任务 ID、错题 ID、导出 ID、响应码、页面截图和后端事件日志；失败项须修复后重跑。浏览器使用 PC Web。

| 步骤 | 动作与预期 |
|---|---|
| 1 | 学生 A 登录，菜单仅显示已授权入口；刷新和重新登录后菜单一致。 |
| 2 | 上传多页 PDF，同一 `clientRequestId` 并发/顺序重复提交，任务 ID 相同；刷新后保留任务。 |
| 3 | 等待分页/OCR，验证逐页原图、灰度预览、低置信提示；故意让 OCR 失败并重试，终态必须为待确认或明确失败。 |
| 4 | 调整、拆分/合并题框，批量确认；重复确认及弱网超时重发不得创建第二份错题。 |
| 5 | 在错题详情订正，进入今日复习；先保存答案曝光前草稿，再看答案并反馈。无草稿或看答案后补写的反馈不得自动掌握；跨三个到期时间独立正确后才能掌握。 |
| 6 | 打开首页、学情报告、家长周报核对同日同名指标；零样本显示“样本不足”。 |
| 7 | 创建专项练习并导出 PDF/DOCX，下载内容与归属账号相符；学生 B 访问 A 的导出、文件和题目 ID 被拒绝。 |
| 8 | 家长绑定 A 后可读授权汇总；解绑后原链接和导出均被拒绝。 |

将 OCR 提供方断开、让执行器队列到达容量、在任务排队和处理中分别重启实例、模拟浏览器请求超时并重发，记录最终状态、重试次数和文件残留。运行期不得凭本地单元测试将本表签为通过。

## 对象归属与权限矩阵（B05/B06）

| 对象 | 所有者校验入口 | A→B 必拒绝动作 |
|---|---|---|
| 错题与订正 | `WrongQuestionService.checkWrongQuestion`、创建人过滤 | 详情、修改、删除、订正、知识点绑定 |
| 采集任务/页/题块 | `QuestionCaptureServiceImpl.checkTask`，页/题块反查任务 | 详情、重试、修框、合并、确认 |
| 源文件与下载签名 | `FileService.checkUserFile`、文件下载授权 | 跨账号挂载、读取、签名下载 |
| 复习项目与反馈 | `ReviewItemService.checkReviewItem`、用户/请求 ID 校验 | 取答案、提交草稿和反馈 |
| 练习会话/卷/导出 | 各 `check*` 服务按当前用户过滤，导出任务按用户查 | 详情、作答、导出、历史下载 |
| 家长概览与代上传 | 有效 `student_guardian_rel` 校验，代上传需学生确认 | 未绑定/已解绑汇总，替学生确认 |
| 系统管理 | `@PreAuthorize` 资源码、菜单角色关联 | 学生调用用户、角色、资源、菜单、字典管理 |

前端每次导航重新读取后端菜单，管理页直达无权限时进入 403 页，401/失效会话进入重新登录页；切换账号后重新获取菜单。后端资源和对象归属仍为最终判定。家庭协作菜单经新增迁移授予现有角色，数据读取继续按绑定关系判定。菜单/资源变更后需验证在线权限缓存刷新；迁移新增菜单后现有登录会话需重新登录。

## 指标与 OCR（B04/B07/B08）

有效复习 = 有曝光前一致的独立草稿且正确性已判定的复习记录；独立正确率/保持率 = 有效记录中的正确数 ÷ 有效记录数。首页和报告掌握率 = 已掌握错题数 ÷ 学生全部错题数；逾期 = 下次复习时间早于当天 00:00。按当前学生、科目、时间窗口取数，错题按 ID 去重。零分母呈“样本不足”；30 日保持率少于 3 条有效记录标为可靠性不足。采集中的“灰度预览”仅做灰度转换，原图始终可切回，不能作为去笔迹结果宣传。

`docs/ocr-samples/` 中仅有脚本用的合成样本。真实评测须获得授权、去标识化并按学科/字迹/公式图形/质量/页数分层，保存在受控存储；用 `scripts/evaluate_capture.py` 固定真值跑每个提供方和模型版本。报告需记录题块召回、关键字段准确率、人工修正时间、失败原因和 P95。真实基线出来后确定上线阈值；合成样本的结果不能用于阈值判断。

## 采集可靠性与门禁（B09/B10）

事务提交后才派发 PDF/OCR，避免消费者读到未提交的任务。超时恢复使用状态与更新时间抢占，最多自动重试 3 次；执行器拒绝时记录指标并由调用线程执行，避免静默丢失。告警阈值与处置见 [P0 安全运行手册](../p0-baseline-and-security-runbook.md)。PDF 渲染使用内存和受控原文件流，未创建独立临时 PDF；上传过程的失败文件清理由文件存储实现处理。预发须特别核对分页中断时已落库页及原图引用，不可直接按文件年龄清理。

`.github/workflows/p0-gate.yml` 在 PR 上执行后端测试（含权限回归）、前端构建、SQL 清单校验和采集评测脚本自检；`scripts/verify-p0.sh` 可在本地执行同组检查。仓库管理员还须把此检查设为合并前必过；预发真实样卷与空库/升级库二次启动结果作为发布清单附件人工确认。只有固定提交、全部门禁和上表真实链路均通过，才能标记 P0 验收完成。
