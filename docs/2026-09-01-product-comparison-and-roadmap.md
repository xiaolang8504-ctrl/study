# 智错本功能对比与后续规划

> 版本：2026-09-01（基于当前工作区代码、前端页面、SQL 迁移脚本及竞品公开资料）
> 产品对象：K12 学生错题采集、订正、复习与练习系统；不是供应链管理系统。
> 阅读说明：`已具备` 代表能在当前代码或前端中找到完整入口；`部分具备` 代表已有数据模型/接口/页面之一，仍缺少完整体验、验证或运营闭环；`未见` 代表本次代码检索未找到对应产品能力。

## 1. 结论摘要

当前仓库已经从旧的供应链项目骨架，演进为一个功能密度较高的“智错本”系统：覆盖错题管理、异步采集任务、OCR 切题确认、订正记录、知识点关联、间隔复习、专项练习、相似题、题库治理、个人报告、提醒和 RBAC。其最有价值的基础不是简单的“电子错题本”，而是已有答案曝光记录、独立作答结果、掌握度和复习间隔等数据要素。

与当前市场相比，项目在学生 PC 端的“收题—订正—复习—报告”链路已达到可用的中上游水平；在本期范围内，主要落差是整卷净化体验、家长多孩子管理、内容版权与 AI 题目治理、数据合规与生产运维。移动端与教师/班级能力明确不纳入本轮规划。市场上的拍照、去笔迹、组卷、多端同步已基本是标配，建议不要把资源主要投入在复制这些界面，而应优先建立可信掌握度和可解释诊断。

建议产品定位：**“能用独立作答和跨间隔保持，证明错题后来真的会了的智能错题系统。”**

### 2.3 必须先处理的产品/工程治理事项

1. 根 README、根 POM、服务模块名和前端页面标题已统一为“智错本/学习系统”。历史 Java 包路径中仍保留 `com.yunshang.budget`，这是兼容性命名，不得在业务发布中与旧供应链产品混用；如需重命名，必须作为独立兼容迁移实施。
2. 工作区当前有大规模未提交的重命名、删除和新增文件。本文把它们视为“正在开发的现状”，不等同于已发布能力。上线评估前应先冻结基线、跑迁移、回归测试并建立版本标签。
3. 功能虽多但身份模型仍是通用 RBAC；尚未发现学生—家长的授权关系模型。直接开放家长页面会带来越权风险。
4. Spring Boot 2.3、Vue 2 与 Element UI 已处于维护后期。它们不阻塞近期试点，但应在平台重构阶段纳入升级计划，不能无限期延后。

### 3.3 竞争判断

1. **移动端是市场标配，但不属于本期竞争面。** 本期以 PC Web 的文件导入、复杂确认、组卷、报告及家长查看为边界，不承诺相机采集或系统推送。
2. **“AI 自动诊断”正在普及，但不等于可信。** 对学生而言，更有价值的是能回答“为什么错、先补什么、下次何时验证”的解释链，而不是一个不可解释的分数。
3. **本项目最该强化的是学习证据。** 已有 `revealTime`、答案查看、作答、反馈、复习记录、掌握分和 30 日保持率。应将“答案是否已看、是否独立作答、间隔多久、是否再次正确”固化为掌握状态机的依据。
4. **题库治理可成为长期护城河。** 版本、审核、重复题、举报、申诉、A/B 实验已经出现；补齐审核队列、质检指标、版权来源和下架流程后，可持续提升家庭端题目质量。

## 4. 产品路线与详细功能规划

### 4.1 优先级原则

先完成学生单人闭环，再扩展到受控的家长协作和内容规模；每一期都必须有可量化验收，不以“接口完成”代替用户价值。以下工期按一个成熟的 5–7 人跨职能小组估算；实际排期以前述 OCR 供应商评测和题库版权为前置条件。本规划不包含移动端、教师端、班级或学校能力。

| 阶段 | 建议周期 | 目标 | 上线门槛 |
|---|---:|---|---|
| R0：基线与质量 | 2–3 周 | 把正在开发的能力变成可试点版本 | 迁移可回滚、主链路回归通过、文档/版本一致 |
| R1：学生 PC 闭环 | 4–6 周 | 用 60 秒完成整页收题，用证据判定是否掌握 | 采集、订正、复习、报告四链路可用 |
| R2：家长 Web 与家庭协作 | 4–6 周 | 让家长在授权边界内了解和支持学生学习 | 多孩子绑定、周报、提醒与越权拦截通过 |
| R3：内容与智能增强 | 8–12 周 | 扩充高质量练习与个性路径 | AI 内容可追溯、可审核、可降级 |
| R4：平台化持续建设 | 持续 | 数据安全、稳定性、家庭端运营增长 | SLO、隐私权利、内容与模型指标达标 |

### 4.2 R0：基线、质量与上线治理（P0）

| 功能点 | 详细要求 | 技术/数据落点 | 验收标准 |
|---|---|---|---|
| 项目统一命名 | README、Nacos 配置名、服务说明、菜单文案、监控仪表盘统一为“智错本/学习系统”；保留旧名映射表 | 文档、配置仓库、部署脚本 | 新成员可在 30 分钟内完成本地启动与模块理解 |
| 版本冻结 | 将当前工作区大改动分批提交；每批配数据库迁移号、回滚说明和发布说明 | Git tag、SQL 迁移登记 | 测试/预发/生产可定位同一版本；任一迁移可演练回滚 |
| 主链路回归 | 登录 → 上传 → 任务处理 → 题块确认 → 错题 → 订正 → 今日复习 → 报告；覆盖 OCR 失败、重复提交、弱网刷新 | API 集成测试、前端 E2E、测试样卷集 | P0 路径通过率 100%，失败场景可恢复且不重复建题 |
| 采集可观测 | 记录任务 ID、用户/文件、OCR provider/model、页数、题块数、置信度、耗时、失败码、人工修正动作 | `question_capture_*`、日志与指标 | 能按科目/模型/版本统计成功率、P95、重试率和修正率 |

### 4.3 R1：学生 PC 闭环（P0/P1）

#### A. 采集中心（P0）

1. 统一入口支持单题、批量图片、PDF；DOC/DOCX 先明确是否转换为页面，不能支持时在前端禁选，避免“可上传但不可识别”。
2. 任务页展示排队/处理中/待确认/失败，含逐页进度、耗时预估、失败原因和 3 次安全重试；退出后自动保存 24 小时草稿。
3. 在题块卡中高亮低置信度字段；批量设定学科、教材、来源、章节；支持合并/拆分/拖拽边框、跳过与“仅保存图片”。
4. 每页提供原图/净化图切换；净化结果不得覆盖原图；去手写和 OCR 都必须允许人工更正。
5. 去重采用“同用户 + 文本指纹 + 感知哈希”三级提示，默认不阻断，用户可选择合并、仍保存或跳过。

验收：20 组真实试卷中题块召回率 ≥95%，关键字段人工确认后的准确率 ≥90%，OCR/净化故障时 100% 可保存原图并稍后重试。

#### B. 订正与掌握证据（P0）

1. 将状态补全为 `待订正 → 已订正 → 复习中 → 已掌握 → 已归档`，状态迁移必须由服务端校验；再次独立答错自动回到“复习中”。
2. 订正提交至少要求“订正答案 + 错因”；错因使用系统枚举（概念、计算、审题、步骤、记忆、粗心、方法、其他）并允许个人标签。现有字符串保留为展示快照，关系表成为唯一事实源。
3. 详情页显示题目、我的原作答、解析、订正、知识点、原卷定位、答案曝光和状态时间线；所有自动动作标明来源（学生/家长/OCR/AI/系统）。
4. “已掌握”不允许由一次点击产生：要求至少两次未看答案的独立作答正确，且其中一次间隔不少于 15 天；阈值版本化并可 A/B。

验收：答案已曝光的练习不会增加独立正确次数；无订正记录不能转已掌握；任一状态变化可追溯人、时间和依据。

#### C. 复习、组卷与报告（P1）

1. 默认复习节奏采用 1/2/4/7/15/30 天，按反馈、独立正确、难度和逾期调整；首页在反馈后立即展示下一次日期与变化原因。
2. 今日复习默认遮住答案，提供草稿、计时、稍后处理和拍照作答；查看答案后固定进入反馈，不将其计为独立正确。
3. 个人组卷支持按科目、知识点、状态、难度、错因选择原题或审核相似题；生成题目版/答案版、A4 留白、二维码/短码。
4. 先把现有浏览器打印和 HTML Word 下载明确标记为“基础导出”；再建设服务端 PDF/标准 DOCX 模板、异步导出任务和下载历史。
5. 报告展示新增/订正/到期完成/首次独立正确/30 日保持/逾期量、薄弱 TOP10、错因分布及下周可执行建议；样本不足时只展示原始数据和提示。

验收：用户能从报告一键发起下一项任务；打印后可用短码回填练习结果；小于 3 条有效样本不展示强结论。

### 4.4 R2：家长 Web 与家庭协作（P0/P1）

本阶段仅建设与学生端同一套 PC Web 体系下的家长页面，不建设移动 App、小程序、教师、班级或学校角色。

| 子能力 | 功能细化 | 权限与数据规则 |
|---|---|---|
| 家长账号与绑定 | 受控邀请码/学生确认绑定；一个家长可绑定多名孩子；一个学生可绑定多位监护人；展示绑定状态、最近登录和解绑入口 | `student_guardian_rel` 必须记录邀请人、确认人、关系、有效状态、创建/撤销时间；绑定和解绑写入审计 |
| 家长首页 | 孩子切换、今日到期量、7 日完成率、订正率、逾期数、薄弱知识点和本周建议 | 默认只展示汇总数据；原题图片、原始作答、答案解析按学生/监护人授权范围控制 |
| 周报与提醒 | 每周新增错题、订正、有效复习、保持率、逾期、下周建议；站内消息和邮件提醒偏好 | 家长只接收学习提醒和周报，不接收题目答案或学生作答内容的默认推送 |
| 受控协助 | 家长可上传文件并创建“待学生确认”的采集任务，可协助整理来源/教材；学生确认后才创建错题 | 家长不能提交订正、查看答案、填写四级反馈、改变掌握状态或删除学生学习记录 |
| 家庭数据与退出 | 家长可导出其有权查看的汇总报告；学生、家长均可发起解绑；未成年人删除/导出遵循监护关系和审计 | 每次导出、查看原题、绑定、解绑和代上传均记录操作者、对象、时间和来源 |

验收：一个家长可正确隔离管理多名孩子；家长账号无法提交“掌握”、订正或复习反馈；解绑后立即失去孩子数据访问权限；所有受控协助均可追溯到实际操作者。

### 4.5 R3：内容、AI 与个性化路径（P1/P2）

| 能力 | 详细规划 | 必要护栏 |
|---|---|---|
| 知识图谱 | 教材版本—章节—知识点—前置依赖—题目关系版本化；错题和题库使用关联表，不再只使用逗号文本 | 图谱来源、适用年级和版本可查询；无样本不推断掌握度 |
| 相似题/AI 变式 | 优先从审核题库召回；AI 只补空缺，保留题源、模型、提示版本、参数、解析和校验结果 | 必须可解性校验、重复检测、人工抽检、举报下架；不能直接作为标准答案 |
| 自适应路径 | 输入前置知识点、独立正确率、间隔保持、错因、考试日期与每日预算；输出 10–30 分钟任务序列 | 展示“为何推荐”；允许学生调整；不对少样本作强推荐 |
| 内容运营 | 题目审核队列、版权证明、版本下架、质量抽检、投诉 SLA、相似题效果看板 | `provider/external_id/license/expire_at/audit_status` 入库；侵权或错误题一键撤回 |
| 实验平台 | 复习间隔、推荐排序、页面引导采用灰度和 A/B；预先定义样本、指标、停止条件 | 不把未验证模型结论直接影响学生掌握状态或家长决策 |

验收：每道 AI/外部题能追溯来源与审核；错误题举报可在 SLA 内下架；实验能产出完成率、独立正确率和保持率的显著性结论。

### 4.6 R4：安全、可靠性与商业化（持续）

1. **隐私与未成年人保护：** 最小化采集，敏感字段加密，导出、注销、删除、恢复、分享撤销、监护人同意和数据保留期限形成完整闭环；访问、导出、授权和删除全部审计。
2. **文件与内容安全：** 上传病毒扫描、文件类型内容校验、对象存储私有读、签名 URL、原图生命周期、CDN 鉴权、水印和防盗链。
3. **可用性：** 上传/OCR/净化采用队列与幂等键，OCR 不可用不阻塞错题浏览和复习；设定 API P95、任务 P95、失败率、积压数和告警阈值。
4. **技术演进：** 优先补自动化 API/E2E 测试、CI、数据库迁移工具和环境配置审计；之后制定 Java/Spring 与 Vue 生态的渐进升级路线，不在业务高峰期“大爆炸重写”。
5. **商业化分层：** 免费层保留基础建错题、今日复习和有限采集；家庭会员可提供批量识别、导出、多人管理和增强报告。收费点必须不损害学生的数据导出与基础复习权利。

## 5. 数据模型与 API 改造清单

| 优先级 | 新增/改造对象 | 用途 |
|---|---|---|
| P0 | `wrong_question_timeline`、`answer_exposure_event`、状态迁移规则 | 将订正、查看答案、独立作答、掌握判断变为可审计证据 |
| P0 | `wrong_question_tag`、`user_tag`、`wrong_question_tag_rel` | 取代 `errorLabels` 的逗号文本；保留原字段作显示快照 |
| P0 | `knowledge_point_relation`、题目/错题知识点关联版本 | 取代 `learningPoint` 的单文本事实来源，支撑前置依赖和统计 |
| P0 | `question_capture_task/page/region` 完整迁移、任务事件与指标表 | 将现有采集雏形稳定为可重试、可观测的异步流程 |
| P1 | `practice_paper/item/result`、`export_task`、`paper_code` | 支撑标准导出、打印、二维码/短码回填和历史追溯 |
| P1 | `learning_metric_daily` | 每日快照支撑趋势分析，避免报表实时全表扫描 |
| P1 | `data_consent`、`share_link`、`audit_log` 扩展 | 支撑授权、可撤销分享、隐私权利和合规审计 |
| P1 | `student_guardian_rel`、`guardian_invitation`、`guardian_access_audit`、周报订阅 | 支撑学生—家长绑定、多孩子管理、受控查看和家庭提醒 |
| P2 | `question_source/license/audit`、AI 生成记录与验证结果 | 内容版权、题库质量与 AI 可追溯 |

建议 API 原则：学生接口使用当前身份推导 owner；任务接口使用资源归属做二次校验；异步操作均带 `clientRequestId`；读写接口返回数据版本与更新时间；敏感导出/分享使用短期、可撤销凭证。

## 6. 成功指标与决策看板

| 漏斗/质量域 | 北极星或核心指标 | 建议首期目标 |
|---|---|---:|
| 北极星 | 每周完成有效复习、且在下一间隔仍保持掌握的错题数 | 作为总目标，不以单纯 DAU 替代 |
| 采集 | 上传 → OCR 成功 → 确认 → 创建错题转化率 | ≥70%（按真实试卷样本校准） |
| 采集质量 | 题块召回率 / 关键字段确认后准确率 / 人工修正率 | ≥95% / ≥90% / 持续下降 |
| 订正 | 新增错题 7 日订正率 | ≥60% |
| 复习 | 到期任务 7 日完成率 | ≥55% |
| 学习效果 | 首次独立正确率 / 30 日保持率 | 先建立基线，再做提升目标 |
| 内容质量 | 举报率、审核 SLA、相似题完成后正确率 | 必须按题源、学科、模型分桶 |
| 可靠性 | 核心 API P95、采集任务 P95、任务失败率 | <800ms、单页 <20s、<2% |
| 安全 | 越权访问成功数、敏感导出无审计数 | 均为 0 |

## 7. 近期决策建议

1. 首发范围固定为“学生 PC Web + 家长 Web”，不建设移动端、教师端、班级或学校功能；菜单、接口、数据模型和排期均以此为边界。
2. 用 20–50 组真实试卷对 OCR、公式、切题和去笔迹供应商进行盲测，按学科、清晰度、手写量分层；在结果出来前不锁定单一供应商或承诺识别准确率。
3. 明确题库版权来源和 AI 内容审核责任人；没有内容治理，就不要把自动生成题作为规模化卖点。
4. 先以 R0 + R1 做 50–100 名学生封闭试点，再邀请其家长进入 R2；观察“确认率、7 日订正率、到期完成率、独立正确/保持率”以及家长周报阅读率、提醒关闭率和家长代上传后学生确认率。
